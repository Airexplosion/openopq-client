# 按现象排查

先划分故障发生在哪一步。网页能打开，说明管理页面可达；QQ 已上线，说明账号会话已建立；收到事件，才说明机器人和网关的事件通道已接通。

| 现象 | 优先检查 | 验证 |
| --- | --- | --- |
| 启动即退出，提示 FakeSignApi | 实际读取的配置文件；URL 需含协议、主机和 /sign 结尾 | 显式指定 --config 后观察启动输出 |
| 网页打不开 | 进程是否退出、端口是否占用、是否使用 --headless | 在客户端所在机器打开启动日志给出的地址 |
| 控制台正常，HTTP 接口返回 401 | 账号对应的 HTTP Token、Bearer 请求头 | 用同一 Token 查询 get_login_info |
| HTTP 正常，WS 握手失败 | WS Token、路径、端口、当前账号的 WS 开关 | 用控制台复制的外部 WS 端点重连 |
| 能查资料，收不到事件 | 是否连接到只处理动作的 /api；反向 WS 的连接角色 | 换用 Universal 或 Event，发一条测试群消息 |
| HTTP 200 但动作无效 | 响应里的 retcode、wording 或 message | 先查支持的动作，再核对参数和账号权限 |
| 媒体接口报找不到 silk 或 ffmpeg | 客户端实际安装目录、程序架构和工具路径 | 按[语音工具说明](../examples.md)检查两个可执行文件 |

反馈问题时附客户端版本、协议、动作名、错误码和复现时间。可从[运行诊断](../console/diagnostics.md)导出脱敏快照。
